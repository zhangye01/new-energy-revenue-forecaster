## 独立自审与修复（2026-11-13，第二轮）

本轮分别审查数学公式、草稿/预测/恢复状态链、编辑器交互。除原有用例外，独立检查年度增长、逐月手算、典型日与8760守恒、负联络线、双向净零和负剩余需求，未发现核心公式或正负方向错误。

| 问题 | 原行为及影响 | 修复与复验 |
| --- | --- | --- |
| 未应用批量输入未受保护 | 粘贴矩阵或输入批量增长率后，可能仍以旧值保存/生成；切换元素会丢掉矩阵，恢复配置却不清辅助输入 | 纳入未提交守卫，保存/生成和元素/方向切换前要求应用或清除；恢复成功同时清空辅助输入，失败保留。真实浏览器确认切换与保存被阻止，恢复后矩阵和批量框为空 |
| 全零小时行与零月份口径冲突 | 月电量为0时手填可通过，但矩阵粘贴无条件拒绝该月全零小时行 | 解析器只校验维度与有效非负数，生成阶段校验正电量月份。浏览器实测1月权重0、小时全0，1月输出为0且全年仍876000MWh；改1月权重为1则明确拒绝，已保存配置保持原值 |
| 已保存来源校验不完整 | 损坏备份的版本、日历、单位、小时数或年度摘要，可能仍被判为有效来源 | 完整核验来源元数据、配置快照和年度摘要。浏览器将合成副本单位改为kWh后经实际sanitizeProject恢复：activeRunId为null，受损run原文保留，原项目未变；集成测试进一步验证基准变为stale_run，原费用/粗算/结果逐值保留 |
| 稀疏数组绕过接口检查 | 仅有length但缺年度项的JS数组可跳过forEach校验 | 年度与典型日数组必须逐项存在且为有效对象；稀疏、空项和非对象输入回归均拒绝 |

来源校验使用新增 `buildAnnualSummary` 共用年度计算；测试明确禁止调用8760构建器，验证30年多版本检查不会反复展开小时数据。完全没有供需来源字段的历史run继续兼容；已有来源但字段损坏的run不能降级为历史版本放行。

修复后重新运行完整 `npm run check`，73个测试文件、70源文件语法及其余全部门禁通过。实际浏览器用独立合成项目复验批量25%增长明确应用后正常生成三模型，原粗算和收益参数未变。界面继续保留“模拟·未使用供需”标识，当前演示定价算法的边界不变。
