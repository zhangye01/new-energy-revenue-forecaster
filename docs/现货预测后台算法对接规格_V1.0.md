# 现货预测后台算法对接规格

版本 V1.0 · 2026-11-18 · 前后端联调依据

**真实预测链路为「构建并冻结全周期小时供需 → 后台算法读取并计算 → 返回现货价格曲线 → 校验并设为生效 → 收益细化与基准测算 → 对照原粗算」。** 供需数据实际进入算法执行，后台价格成为后续测算的价源。

当前前台已能构建小时供需、保存输入来源并运行模拟预测。本文规定正式接线和验收方式。开发对接时仍需落实后台算法服务、正式接口地址、身份凭证、模型及价格口径。

## 1. 前台、后台和算法各负责什么

|环节|责任|完成条件|
|---|---|---|
|构建供需|前台填写年度电量与增长率，结合 Excel 和界面配置默认曲线及指定年曲线，保存后生成全周期小时数据|界面显示待确认的改动。用户校验并确认保存后，生成供需输入版本|
|提交预测|前台发起任务。应用后台核对项目权限、测算边界和输入版本，冻结实际算法输入|服务端登记运行ID，并确认实际输入文件或序列可读|
|计算现货价格|算法读取该运行的六项小时序列或按约定从这六项生成的特征|返回覆盖全周期的现货价格和本次使用的模型、输入版本及计算状态|
|结果回传|应用后台校验、落库。前台按运行ID查询状态及结果|校验合格的运行成为可选预测版本，用户设为生效后可用于基准测算|
|收益及验证|用户核对收益参数。系统使用该生效价格与项目小时结算电量计算基准，交叉验证读取已保存基准和原粗算快照|给定任一基准结果能定位到明确的预测运行和输入。原粗算仍可查看和对照|

前台可以在任务运行时编辑收益参数草稿。用该次新预测生成基准，须等价格回传、通过校验并生效后开始。模拟价格、外部给定价格和后台算法价格各有独立来源标记。

## 2. 后台算法的实际输入

### 2.1 提交信息和输入版本

|字段|内容|
|---|---|
|运行标识|应用后台生成的 `forecast_run_id`，贯穿提交、查询、接收结果和收益测算|
|项目与市场|`project_id`、`market_area_id`、预测目标口径；如采用分区或节点，包含对应标识|
|测算周期|`start_year`、`forecast_years` 从项目读取，覆盖每个模型年|
|供需版本|`supply_version_id`、`input_snapshot_id`、供需生成清单的输出校验和|
|输入格式|`input_schema_version`、`calendar_type=fixed_365_days`、`interval_minutes=60`、`energy_unit=MWh`、`hour_index_base=1`|
|实际供需|上传全周期小时数据，或提交算法端有权限读取的不可变数据引用。后台必须能按引用读取实际序列并核对点数及校验和|
|其他模型参数|`model_code`、约定的特征和规则版本、运行参数。后台返回实际执行版本|

数据已有后台受控文件时，提交运行只需发版本引用。数据只在前台时，先上传并校验，再发起预测。大数据可按年份提交，封存完整输入后才允许跑模型。模型运行期间均使用同一输入快照。

### 2.2 小时数据口径

基本粒度为一个模型年中的一个小时。采用宽表时，每年有 8,760 行，每行提供以下六个元素的该小时 MWh。也可保持现有 `hourlyByYear[year][elementCode]` 结构，约定数组第一个元素对应 `hour_index=1`。保持完整年份、时序及数值精度。

|元素代码|名称|口径|
|---|---|---|
|`load`|省内负荷|非负|
|`tieLine`|联络线负荷净额|正数送出、负数受入。双向配置时可额外传送出和受入两列作为核对信息|
|`wind`|风电出力|非负|
|`solar`|光伏出力|非负|
|`hydro`|水电出力|非负|
|`nonMarket`|非市场化出力|非负，按独立可配置元素传入|

可带 `residualDemand`，计算为省内负荷加联络线净额，减去四类出力。它可作为衍生特征，允许为负。六项原序列仍应随输入一同可查。固定 365 天模型年的月份天数按现有规则，哪一年是自然闰年都使用同一模型时段编号。若算法使用真实日历或更细粒度，须明确映射或转换版本、校验总量，并在联调时验证时段对齐。

## 3. 结果回传与生效规则

按长任务接口设计。提交接口返回运行ID及状态，前台以运行ID查询。算法和应用在同一服务时可直接记录完成结果。算法由独立服务执行时，应用后台通过双方约定的状态查询或经认证的回传接口接收结果。前台统一走应用接口。

|操作|建议路径|完成约定|
|---|---|---|
|提交|POST /api/forecast-runs|提交冻结输入及幂等键，返回应用生成的运行ID和状态。后台尚未完成计算时显示排队或运行中|
|查状态|GET /api/forecast-runs/{id}|返回运行状态、结果校验状态、可采用状态及错误；刷新可恢复查询|
|取结果|GET /api/forecast-runs/{id}/prices|按模型年读取已校验的价格点或结果文件；价格始终关联运行ID|
|采用|POST /api/forecast-runs/{id}/activate|带预期项目修订号和原生效版本。服务端核对当前供需与项目边界，原子更新生效指针|

|返回内容|最少字段与校验|
|---|---|
|身份和输入|`forecast_run_id`、输入快照ID和校验和、实际算法版本、实际读取的特征或输入清单；必须与提交任务对应|
|任务状态|`queued`、`running`、`succeeded`、`failed`，提供可理解的失败原因。重复提交同一请求应返回同一任务，显式重试使用新运行并记录关联|
|价格输出|`result_schema_version`、预测区域和口径、年份、模型日历、原生间隔、价格单位 `CNY/MWh`、完整价格点或可读文件引用、点数、输出校验和|
|配储对比口径|可用于配储增量测算的市场曲线须独立于单个项目的配储参数。核对后，消费侧映射为 `marketPriceBasis=project_storage_independent_v1`，用同一条价格计算有储和无储两侧|
|价格明细|每个原生点含模型年、时段编号、电价。小时价每年 8,760 点，15 分钟价每年 35,040 点。样例、负价、缺失和非有限值分别校验，负价为合法数值|
|评价信息|若有真实评价，返回实际指标、数据集、范围、定义版本，缺评价时显示未评估或不适用。真实回测评价与本次时序完整性校验分别记录|

应用后台先完成覆盖、数值、时序、口径、来源及校验和检查，再将任务结果标为可用。算法执行完成与结果校验通过分别记录。先收到文件、正在校验或文件缺点时，前台显示状态或错误。按现有结算口径，15 分钟原价将每四点取算术平均得到小时价。原生小时价可直接进入项目收益计算。后台输出的实际分辨率应原样标记。

生效时再次核对任务的供需版本和项目边界。任务运行时若提交了新一版供需，旧任务晚到的结果只归档到自己的运行，可查看详情。切换生效在同一事务内校验当前版本并记录。断网或刷新后可按运行ID恢复查看。

若后台任务失败或超时，前台展示原因，并按同一输入或新输入发起重试。重复回传同一输出校验和按幂等处理；相同运行ID尝试回传不同的已封存输出时拒绝并记录。人工放行只适用于约定的质量提示，技术完整性及授权校验始终执行。已有基准及旧价格版本保留历史状态。正式预测请求的结果以后台回传为准，演示曲线只能在用户选择演示流程时使用。

### 下游使用方式

1. 收益计算请求固定一个已生效且适配当前输入的 `forecast_run_id`，同时冻结结算电量和收益配置版本。计算过程中使用同一个价格运行。
2. 成功后保存基准结果和实际价格来源。若价格运行在计算期间被切换，旧任务的结果可以留档，当前总览仍需根据最新有效输入决定是否采用。
3. 交叉验证用粗算快照与基准收益运行的 ID，比较统一口径的年度或全期加权综合电价。后续重算切换的是基准，原粗算继续保留。

## 4. 现有代码接线与落库

|位置|现状与接线点|
|---|---|
|供需生成|沿用 `buildDataset` 的六元素和模型年数据，由应用后台做提交校验。 [supply-demand.js](../src/domain/supply-demand.js#L205)|
|预测提交|将正式运行入口接为提交、轮询和回传适配，成功时按后台实际返回的模型及价格显示。当前同步演示生成走独立入口。 [forecast-run-flow.js](../src/ui/forecast-run-flow.js#L151)|
|预测来源校验|当前校验接受演示标记。接线时按版本区分真实后台与演示来源，分别检查输入版本和合法性。 [price-forecast.js](../src/domain/price-forecast.js#L373)|
|基准收益|将校验通过的后台小时价适配到 `run.pricesByYear[year]`，按现有小时价量口径计算捕获价与收入。 [revenue-calculator.js](../src/domain/revenue-calculator.js#L85)|
|持久化|复用第08表 `input_snapshot`、第23表 `forecast_run`、第24表 `forecast_price_point`；大文件使用第06表，基准计算引用第08表冻结的预测运行。后台另有执行器时，在运行记录保存外部任务ID；按需保存回传时间、校验状态和重试来源。 [数据库字段清单](数据库数据需求与表字段清单_V1.1_20261118.md#6-历史现货与预测运行表)|

前台入口已预备。接口适配器由应用配置的 `backendForecastService` 提供 `submit`、`refresh`、`activate`。面板从服务读取任务ID、项目ID、输入指纹、状态、运行ID和是否可采用。正式结果接线仍需实现真实来源校验、将已采用结果同步到项目的生效预测，并让收益测算读取该运行。继续按钮以项目实际生效且可供测算的真实运行作为判定。

## 5. 联调验收

|用例|验收条件|
|---|---|
|实际输入|在算法执行记录核对实际读取的六项序列、覆盖年份、数值单位及快照校验和。检查联络线负值和非市场化独立元素正确到达|
|供需驱动价格|挑选一组按模型机制预期能够改变价格的供需样本，固定模型、种子和其余参数，修改相应供需时段，核对实际特征、价格变化与算法解释|
|价格进入收益|选若干小时核对后台原价、用于结算的小时价和项目电量，核算贡献并对照捕获价、年度收益及交叉验证。结果来源指向测试运行|
|异常回包|构造错项目、错输入版本、错单位、重复或缺点、非法数值等回包，前台得到可读失败提示，当前有效结果继续可查|
|旧任务晚到|提交甲任务后修改供需并提交乙任务。甲后返回也只留档；采用乙后，基准读取乙对应价格，同时保留原粗算|
|刷新及重试|运行中刷新可继续查看。相同请求幂等，失败后可重试，新旧运行及对应输入可追溯|
|来源区分|以固定样例先验收前后端协议，再用真实模型验收供需对价格和收益的影响。界面展示价格来源、算法版本及是否有真实评价|

验收联动时优先选择一个已确认市场、一段能手工核对的输入和至少一个完整模型年，端到端核对成功后再做多年度与并发压测。算法服务地址、鉴权、最终字段命名、价格目标与间隔、发布规则由前后端和算法团队联调确认。
